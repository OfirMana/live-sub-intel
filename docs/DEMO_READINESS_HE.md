## ראיות

189 בדיקות Python ו־8 בדיקות Node עברו. לפני ההרצה עם גישת localhost, הסביבה החסומה החזירה WinError 10013 בבדיקות רשת; בהרצה עם גישה הן עברו. לא שינינו את הקוד כדי לעקוף בדיקות.

בדיקת הסברים סינתטית: 36 נקודות זמן בחמש דקות, 1,253 תוכניות ו־7,518 הסברים. 15 נקודות עם חילוף, 13 שינוי טקטי בלבד ו־8 ללא שינוי. אלו נקודות בדיקה חוזרות, לא כמות חילופים שבוצעו. בדיקת המחקר ההיסטורית: 72 נקודות, 2,070 תוכניות ו־12,420 הסברים.

בבדיקת דפדפן מקומית בדקה 65, חלופה שנייה של אייב → בנטקה הציגה את פירמינו עובר לכנף ואת בנטקה בחוד; ההסבר התייחס לאייב ולא לחלופה הראשונה. המקור סומן כתבנית בהיעדר Foundry מקומי.

הבדיקות מוכיחות חוזים, עקביות ומניעת טעויות מסוימות; אין הוכחה שההמלצות משפרות תוצאות כדורגל. ניסיון בדיקת API נוסף לאתר Azure נתקל ב־timeout בחיבור מהמחשב הזה; אין לסמן אותו כבדיקה שעברה או להסיק ממנו לבד שהאתר נפל.

## מה נשאר לסיום — סדר עבודה

1. למזג ולפרוס את שינויי הדמו הסינתטי. לבדוק ש־/api/bootstrap מחזיר data_mode=synthetic ושהכותרת באתר מסמנת משחק סינתטי.
2. החבר שמנהל Azure יתקן FOUNDRY_ENDPOINT. הממצא בפריסה הקודמת: CONFIG_ENDPOINT_FORMAT בשלב configuration; לא בקשת ספק שנכשלה. לאחר תיקון צריך source=llm בהסבר אמיתי. אם מופיע כשל נוסף, לבדוק את הקוד ולא לנחש.
3. בדיקת קבלה קצרה אחרי הפריסה והחיבור: חלופה ראשונה ושנייה, שדרן ואנליסט, עברית ואנגלית, שינוי גישה/מטרה, התקדמות וחזרה בזמן, שינוי מערך וחלופה שנדחית. לבדוק שאין הסבר ישן אחרי שינוי בחירה.
4. סקירה כדורגלנית אנושית של מספר מצבים: האם הצורך הגיוני, האם היתרון מצדיק חילוף והאם המחיר ההגנתי סביר. זו אינה משימה שה־LLM פותר. אין לכוון את הסף כדי לכפות שמות או חילופים היסטוריים.
5. צוות ההגשה ישלים סרטון/Pitch באנגלית, צילומי מסך והגשה בפועל. יש לוודא הרשמה ומועדים מול אתר התחרות; עבודה בריפו אינה רישום או הגשה.
6. הצוות יוודא זכויות הפצה וקרדיט לנתוני השחקנים ול־StatsBomb. מקורות פתוחים/נגישים אינם בהכרח מתירים כל הפצה. אין כאן אישור משפטי או טענה שהזכויות כבר נבדקו.
